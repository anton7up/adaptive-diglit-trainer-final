# Протокол последующей проверки на реальных обучаемых

## Цель

Проверить, переносится ли преимущество адаптивной политики из контролируемой симуляции на реальных студентов.

## Дизайн

Рекомендуемый дизайн — проспективный рандомизированный A/B-пилот:

- группа A: ML-адаптивный подбор;
- группа B: случайный или заранее фиксированный неадаптивный подбор;
- стратификация при рандомизации по входному тесту цифровой грамотности;
- одинаковый банк заданий, длительность и критерии завершения;
- заранее зафиксированный primary endpoint и план статистического анализа.

Для exploratory-пилота целесообразно иметь не менее 30 участников на группу; окончательный размер выборки должен определяться power-анализом после оценки дисперсии первичной метрики на пилотных данных.

## Primary endpoint

Предпочтительный первичный показатель:

**количество выполненных заданий до достижения заранее заданного критерия мастерства**.

Дополнительные показатели:

- normalized learning gain pre-test → post-test;
- доля участников, достигших мастерства за фиксированный горизонт;
- retention-test через 7–14 дней;
- время до мастерства;
- число ошибок и повторов;
- dropout/completion rate.

## Анализ

- intention-to-treat как основной принцип;
- доверительный интервал эффекта;
- тест различия между группами на уровне участника, а не отдельных попыток;
- survival/time-to-event анализ, если часть участников не достигает мастерства в пределах горизонта;
- отдельный анализ retention и subgroup diagnostics как вторичные результаты.

## Реалистичный вариант 

1. Подготовить два качественных экзамена
Например:
Экзамен A — входной
18 заданий: по 3 на каждый из 6 навыков

Экзамен B — итоговый
18 других заданий: по 3 на каждый из 6 навыков
Задания должны совпадать по:
проверяемым навыкам;
примерной сложности;
когнитивному уровню;
количеству вариантов;
времени выполнения.
Вопросы экзаменов A и B не должны использоваться во время учебной практики.
2. Провести входной экзамен
Все 60 студентов проходят экзамен A.
На входном экзамене лучше не показывать правильные ответы и объяснения, чтобы студенты их не запомнили.
Получаем начальный уровень:
Студент 1 → 55%
Студент 2 → 72%
Студент 3 → 40%

3. Разделить студентов на равные группы
Не просто первые 30 и последние 30. Сначала нужно учитывать входные результаты.
Например, два студента с близким уровнем:
Студент 1 → 62%
Студент 2 → 61%
Случайно распределяются:
один → ML-группа
второй → контрольная группа
Получается:
30 студентов → ML-adaptive
30 студентов → random или fixed
Так начальный уровень групп будет примерно одинаковым.
4. Провести учебную практику
Обе группы работают в одинаковых условиях:
один банк учебных заданий;
одинаковое количество заданий, например 40;
одинаковое время;
одинаковые объяснения;
одинаковый интерфейс.
Различается только подбор:
Группа A → задания выбирает ML
Группа B → задания выбираются случайно
5. Провести итоговый экзамен
После практики все проходят экзамен B.
Экзамен A → до обучения
Экзамен B → после обучения
Не стоит буквально повторять вопросы экзамена A: студент может помнить варианты ответов. Тогда будет измеряться не только обучение, но и запоминание теста.
6. Сравнить прирост
Для каждого студента:
прирост = результат B − результат A
Например:
ML-группа:
до 55%, после 78% → +23 процентных пункта

Random-группа:
до 56%, после 69% → +13 процентных пунктов
Затем сравнивается средний прирост групп.
Ещё более строгий вариант
Чтобы возможная разница сложности экзаменов A и B не повлияла на результат:
половина студентов: A до → B после
половина студентов: B до → A после
Такое распределение нужно сделать внутри обеих учебных групп.

. Можно и нужно заранее составить экзамены A и B примерно одинаковой сложности. Тогда для первого исследования достаточно схемы:
Все студенты:
экзамен A → практика → экзамен B

Так после эксперимента будут три уровня результатов:
Экзамен: какая группа лучше повысила знания.
Практика: как именно проходил процесс обучения.
ML-метрики: насколько точно модель предсказывала ответы реальных студентов.
